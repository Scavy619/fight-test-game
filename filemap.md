# File map

`path — what lives here / when to touch it`

- `HANDOFF.md` — session handoff: status, next step, decisions. Update after every accepted task.
- `CLAUDE.md` — short rules and commands loaded into every session.
- `docs/SPEC.md` — game design and architecture. Change only with the user's agreement.
- `docs/PLAN.md` — task list, briefs, status.
- `docs/BRIEF.md` — the user's original project brief (full lists of styles, weapons, gods).
- `docs/SETUP-NEW-PC.md` — how to continue the project on another computer (requirements, savvy-flow setup, resume command).
- `claude-setup/install.mjs` — one-command setup of the savvy-flow skill, agents and savvy-progress mod on a new computer.
- `docs/LORE.md` — mythology research (Tradition) and game fiction (In this game) per fighter and arena, future roster backlog, sources.
- `src/content/lore.ts` — typed lore text (`HERO_LORE`, premise, adaptation statement) for the gallery; keep in step with `docs/LORE.md`.
- `package.json` — npm scripts and pinned devDependencies.
- `tsconfig.json` — strict TypeScript settings (typecheck only, no emit).
- `vite.config.ts` — Vite dev server (port 5173, strictPort) and Vitest config.
- `eslint.config.js` — ESLint flat config, including the `src/sim` purity rules.
- `index.html` — page shell with the single `#game` canvas.
- `.claude/launch.json` — preview config running `npm run dev` on 5173.
- `src/main.ts` — entry point: wires canvas, keyboard, mouse, menu, scenes and loop; starts the mode select (`?mode=versus|easy|normal|hard` skips it, `?debug=input` shows inputs).
- `src/engine/canvas.ts` — 1280x720 logical canvas, letterbox scaling, DPR and resize handling.
- `src/engine/loop.ts` — fixed 60 Hz loop: pure `accumulate` step accounting plus `createLoop`; pauses while the tab is hidden.
- `src/engine/input.ts` — key bindings as data, key/gamepad to `InputFrame` mapping, `InputManager`.
- `src/engine/mouse.ts` — mouse input: `mouseToFrame` (cursor and buttons to `InputFrame`, solo play), `MouseInput` (tracks the canvas cursor, keeps short clicks), `canvasToLogical`.
- `src/engine/menu.ts` — edge-triggered menu actions with direction repeat, combined and per player.
- `src/engine/scenes.ts` — `Scene` interface and `SceneManager` stack (set, push, pop).
- `src/engine/context.ts` — `GameContext` type passed to scenes, and `stepGame`.
- `src/engine/debugScenes.ts` — placeholder title scene and the `?debug=input` scene.
- `src/sim/index.ts` — public sim API: `createMatch`, `step`, types, helpers, constants.
- `src/sim/types.ts` — all sim types: `InputFrame`, `MoveDef`, `FighterDef`, `FighterState`, `Projectile`, `MatchState`, `Match`, `SimEvent`.
- `src/sim/constants.ts` — tunable constants (stage, phases, meter, combo scaling, hitstop, chip, dodge, buffer, super freeze).
- `src/sim/match.ts` — `createMatch`, `step`, round and match flow.
- `src/sim/fighter.ts` — fighter state machine: timers, input decisions, cancels, ultimate, landing.
- `src/sim/physics.ts` — gravity, pushback with corner transfer, stage bounds, body push.
- `src/sim/combat.ts` — hit collection, block or hit decision, throws, damage, meter, hitstop.
- `src/sim/projectiles.ts` — projectile spawn, motion (`linear`, `returning`), clash, hits.
- `src/sim/zones.ts` — floor zones: `spawnZones` (from a move's `zone`), `resolveDecoys`, `tickZones` (slow fields, delayed strikes, expiry).
- `src/sim/mechanics.test.ts` — stances, shields, late-guard pierce, zones, returning projectiles, determinism with all of them.
- `src/sim/geometry.ts` — rects, hitbox to world conversion (convention documented here), overlap tests.
- `src/sim/moves.ts` — read-only helpers over move frame data.
- `src/sim/input.ts` — edge detection and the 6-frame press buffer.
- `src/sim/validate.ts` — `validateFighterDef(def)` for content tests; run it on every new fighter.
- `src/sim/testFighter.ts` — complete generic 10-slot fighter used by tests and as a stand-in.
- `src/sim/testHelpers.ts`, `src/sim/*.test.ts` — input scripting helpers and unit tests (`grab.test.ts`: the light + heavy grab trigger and throw rules; `feel.test.ts`: light chains, hold-back block, power strike).
- `src/render/index.ts` — public render API re-exports.
- `src/render/types.ts` — `Bone`, `Pose`, `Keyframe`, `Animation`, `AnimationSet`, `FighterLook`, joint names; the angle convention is documented here.
- `src/render/anim.ts` — `samplePose` and pose interpolation helpers.
- `src/render/rig.ts` — skeleton dimensions, forward kinematics (`computeRig`), two-bone IK, weapon specs.
- `src/render/pose.ts` — `pose()`, `key()`, `anim()` authoring helpers (degrees, IK targets); use these to write animations.
- `src/render/fighterView.ts` — `createFighterView(look)`: draws body, head, ribbon, weapon, trail and ground glow.
- `src/render/neon.ts` — palette and neon drawing helpers (capsules, rim strokes, energy lines).
- `src/render/heads.ts` — the four head silhouettes and visor.
- `src/render/weapons.ts` — katana, spear, staff, hammer.
- `src/render/chain.ts` — follow chain for ribbons, braid and ponytail.
- `src/render/color.ts` — colour helpers.
- `src/render/sampleLooks.ts` — reference looks: the prototype looks (Rei, Vira, Wukong, Thor) and `ASTRA_LOOKS` (the eight heroes; Arjuna and Bhima come from their hero files). `/gallery.html?set=astra` shows the ASTRA set.
- `src/render/anims/base.ts` — `baseAnims`: shared animations for every state and the generic move slots.
- `gallery.html`, `src/gallery.ts` — dev-only rig gallery at `/gallery.html` (`?anim=&frame=&facing=-1&zoom=&focus=&drift=1`).
- `src/render/fighterAnim.ts` — `pickAnimation` (sim state to animation id and frame) and `FighterAnimator` (blending, trail on active frames).
- `src/render/hud.ts` — HUD state (damage ghost, combo pop) and drawing: health, names, pips, timer, meter, combo, announcer.
- `src/render/actionBar.ts` — solo mouse action bar: button layout, hit test, drawing (`drawActionBar`); the solo controller in `modeSelect.ts` feeds it.
- `src/render/controlsHelp.ts` — on-screen controls text (one source for the key names): `drawControlsStrip` above the meters in the fight, `drawControlsPanel` for the pause overlay and the mode select.
- `src/render/projectileView.ts` — `drawProjectile` by `ProjectileLook` kind (arrow, orb, shockwave, axe).
- `src/render/zoneView.ts` — `drawZones` and `drawDecoyOutline`: strike lanes, marks, slow fields, decoys with text labels.
- `src/render/statusLabels.ts` — `statusLabels` (pure) and `drawStatusLabels`: SHIELD, ARMOR, CHARGING, SLOWED, STANCE tags over a fighter.
- `src/render/portrait.ts` — `drawPortrait`: procedural hero card from the real rig (select, gallery, campaign), `roundRect`.
- `src/render/kit.test.ts` — draft looks, weapon specs, palettes, status labels.
- `src/render/stage.ts` — procedural stage with palettes (`STAGE_PALETTES`, `drawStage`, `GROUND_Y`); parallax arenas are a later phase.
- `src/render/sparks.ts` — placeholder hit and block sparks; task 8 replaces them with particles.
- `src/content/heroes/index.ts` — hero registry: `HEROES`, `HERO_ORDER`, `HeroId`, `BODY_STRIKES`. Register new heroes here.
- `src/content/heroes/arjuna.ts`, `bhima.ts` — one file per hero: stats, 12 moves, look, animations, visuals, projectile looks and the profile (bio, move descriptions, unlock). Copy one as the template.
- `src/content/heroKit.ts` — authoring helpers: `tipBox` and `weaponPoints` (hitboxes and projectile spawns from the strike pose), `attackAnim`, `idleAnim`, `walkKeys`, `info`, shared cancel lists.
- `src/content/roster.ts` — the full eight-hero roster (names, titles, unlock text) the select screen shows, including heroes not written yet.
- `src/content/heroes/heroes.test.ts` — tests every hero must pass (validation, animation lengths, weapon tip versus hitbox, projectile spawns, walk stride, grab and power rules, profile completeness, lore). `combos.test.ts`: random combo bounds over every pairing. `chains.test.ts`: light, light, heavy as one combo and the ultimate trigger.
- `src/scenes/campaign.ts` — story campaign scenes; `src/scenes/dialogue.ts` — dialogue box scene; `src/content/campaign.ts` — the eight chapters and pure step resolution (`campaign.test.ts`).
- `src/scenes/arcade.ts` — Arcade: hero pick, ladder fights, continue and ending cards, saves the clear and grants unlocks.
- `src/scenes/card.ts` — `createCard`: heading, progress dots, portraits, wrapped text and choices (Arcade now, the campaign later).
- `src/content/unlocks.ts` — `UNLOCK_RULES`, `unlocksFor`, `grantUnlocks`; `src/content/arcade.ts` — `ARCADE_RIVALS`, `buildLadder`, `ARCADE_ENDINGS`; `src/content/unlocks.test.ts` tests both.
- `scripts/balance.ts` — AI-versus-AI round robin matrix (`npm run balance`); `scripts/tune.ts` — health and power coordinate search.
- `src/ai/balance.test.ts` — guards every hero's overall hard win rate between 25% and 75%.
- `src/content/heroes/parashurama.ts`, `ashwatthama.ts` — the last pair of heroes (Ashwatthama has stances).
- `src/content/heroes/karna.ts`, `ghatotkacha.ts` — the third pair of heroes.
- `src/scenes/practice.ts` — Practice: dummy menu, `startPractice`, dummy controllers, move-list HUD, reset and refill hooks.
- `src/scenes/gallery.ts` — Character gallery: grid, hero detail tabs (`tabContent`, pure), animated preview (`previewAnims`).
- `src/scenes/soloControls.ts` — `createSoloHuman`: keyboard, pad and mouse human controller plus the action bar overlay.
- `src/scenes/scenes.test.ts` — practice dummies and gallery content tests.
- `src/content/heroes/ekalavya.ts`, `abhimanyu.ts` — the second pair of heroes (see arjuna.ts for the template).
- `src/scenes/charSelect.ts` — character select (eight tiles, info panel, locked and coming-soon states); `heroAvailability`.
- `src/render/text.ts` — `wrapText`, `drawWrapped` for menu text.
- `src/render/moveVisuals.ts` — data-driven move visuals (`column`, `burst`, `streak`) spawned from sim `fx` tags via `FighterEntry.visuals`.
- `src/scenes/fight.ts` — the fight scene: runs the sim, animators, HUD, shake, flash; `FightConfig` takes controllers (AI hook) and event listeners (effects, audio hook). Backquote toggles the hitbox debug overlay.
- `src/scenes/pause.ts` — minimal pause overlay; heavy (back) leaves to the menu when the fight has `onExit`.
- `src/scenes/mainMenu.ts` — ASTRA title and main menu (Story, Arcade, Versus CPU, Two Players, Practice, Gallery, Controls; unfinished modes disabled with the slice named), `startMode` (also the `?mode=` deep link), the solo mouse controller and the controls gate before the first fight.
- `src/scenes/listMenu.ts` — shared `ListMenu` (keyboard, mouse, pad), menu backdrop, ASTRA wordmark, adaptation notice.
- `src/scenes/controlsScreen.ts` — full controls screen; sets `save.seenControls`.
- `src/engine/save.ts` — `SaveStore`: versioned localStorage save (unlocks, campaign progress, arcade clears, settings) with safe defaults and an in-memory fallback.
- `src/content/types.ts` — `FighterEntry`, `HeroProfile`, `MoveInfo`, `UnlockRule`, `ProjectileLook`, `HeroEntry` (the one data source for select, gallery, practice and combat).
- `src/ai/controller.ts` — `createAi(difficulty | AiParams, seed)`: the AI opponent (delayed view of the opponent, think timer, block/dodge, punish, anti-air, cancels, ultimate), `DIFFICULTIES`, `moveReach`.
- `src/ai/rng.ts` — seeded RNG (mulberry32) used by the AI.
- `src/ai/simulate.ts` — `runAiMatch`: headless AI-versus-AI match (tests, task 14 balance runner).
- `src/ai/ai.test.ts` — determinism, activity, hard-beats-easy, reach tests.
- `src/sim/` — (task 3) pure combat simulation and its tests.
- `src/engine/` — (task 2) loop, input, scene manager.
- `src/render/` — (task 4) rig, animations, drawing, HUD, effects, arenas.
- `src/content/` — (tasks 5, 7, 11, 13) fighters, arenas, lore data, registries.
- `src/audio/` — (task 12) synthesized sound.
- `src/scenes/` — (tasks 6, 10) title, select, fight, results, lore.
- `scripts/` — (task 14) balance runner.
